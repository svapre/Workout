Context:
This app is a structured training / practice app with this hierarchy:
- Activity = canonical identity record
- Routine = executable script built from activity blocks
- Stage = progression layer
- Plan / Active Plan = higher-level structure and runtime state

Current architectural rule:
- The routine is the source of truth for the player.
- If the player needs a distinct screen/state for something, that thing should exist as a distinct block in the routine.

Current routine/player model:
- Activity entry = parent block
- Nested blocks inside an entry:
  - work
  - rest
  - switch_side
- Between-entry connector:
  - transition / reset before next activity

Recent changes:
- Work blocks can now explicitly own:
  - metricType (`reps` or `duration`)
  - side (`left`, `right`, `both`, `alternating`)
  - holdSeconds
  - tempoLabel
- Simple unilateral entries can use `sideMode`, which auto-expands into explicit left / switch / right flow
- Routine Detail now renders denser script cells for block facts like side / target / load / hold / tempo
- Player now reads block-level metrics directly, so timed alternating blocks no longer show irrelevant rep inputs
