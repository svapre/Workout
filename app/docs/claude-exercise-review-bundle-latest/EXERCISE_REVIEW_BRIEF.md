# Exercise Library / Detail Review Brief

This packet is for a narrow framework review of the exercise surfaces only.

## Review Goal

Decide whether the following screen group is framework-complete or still needs another pass before beautification:

- Exercise Library
- Exercise Detail

## Current Product Rule

- Exercise Detail is the canonical owner surface for an activity record.
- Higher layers should embed only the compact exercise preview.
- New exercise metadata should appear on Exercise Detail first by default.

## What the Current UI Is Trying To Do

### Exercise Library
- Provide search + scope + category filtering
- Let users scan a mixed catalog of physical, mental, and mind-body records
- Show a compact summary with title, visual, focus, equipment, and tracking

### Exercise Detail
- Show the full owner record
- Use a large primary visual chosen by domain
- Surface key facts clearly in the hero
- Push deeper profile/supporting context into disclosures

## Current Concern

The strongest open framework question is the library compact contract:

- The cards are visually homogeneous and repeated.
- The small visual may still communicate target/body area more strongly than movement/practice identity.
- The library may be too card-heavy for discovery content that could scan better in a denser list/hybrid pattern.

The current detail screen appears stronger than the library, but the attached screenshots are still mostly a physical example (`Band Row`).
This refreshed packet now includes both phone-landscape and phone-portrait exercise surfaces so the review can judge compact behavior across tighter mobile layouts as well.

## What We Need Claude To Judge

1. Is the Exercise Library still structurally wrong?
2. Is the current compact visual contract incomplete?
3. Should the library become more list-like / less card-heavy?
4. Is Exercise Detail already owner-surface complete?
5. Is another framework pass still needed before beautification for this screen group?
