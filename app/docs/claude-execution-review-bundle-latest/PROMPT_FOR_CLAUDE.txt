Context:
This app is a structured training / practice app with this hierarchy:
- Activity = canonical identity record
- Routine = executable script built from activity blocks
- Stage = progression layer
- Plan / Active Plan = higher-level structure and runtime state

Current architectural rule:
- The routine is the source of truth for the player.
- If the player needs a distinct screen/state for something, that thing should exist as a distinct block in the routine.

Current routine/player model:
- Activity entry = parent block
- Nested blocks inside an entry:
  - work
  - rest
  - switch_side
- Between-entry connector:
  - transition / reset before next activity

Recent changes:
- Rep-based work blocks now use explicit rep goals:
  - `exact`
  - `max`
  - `minimum_plus` (e.g. `6+ reps`)
- `Max reps` is no longer shown as a separate effort chip in rep blocks
- Routine Detail now uses a flow-first execution lane rather than a document/table-first presentation
- Tempo is now rendered as explicit phase guidance instead of shorthand:
  - phased example: `Down 3s`, `Bottom hold 1s`, `Up 1s`, `Top hold 1s`
  - cadence example: `Each rep 4s`
- Player now shows open-ended rep goals as a `Goal` fact and asks for `Actual reps`
- Seeded manual-check content now includes:
  - `Parameter Extremes Routine`
  - `Max Reps Check`
